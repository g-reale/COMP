<p align="center">
  <strong>Compilers</strong>
</p>

This repository contains the implementation of a **compiler** for a custom programming language called `g--`, developed as a project for the Compilers course at the Federal University of São Paulo. The compiler translates programs written in `g--` — a simplified subset of C with support for integers, arrays, functions, and control flow structures — into an executable binary format for a custom processor architecture. The complete pipeline includes lexical analysis, syntax analysis, and assembly code generation.

## Objective

- Implement a complete compiler including Lexer, Parser, and Assembler stages.
- Define a formal grammar for the `g--` language and generate the LL(1) parsing table.
- Translate high-level programs into instructions for a custom processor architecture.
- Explore concepts of expression parsing, declarations, scope, and function calls.

## Technologies Used

- **Implementation Language:** C++
- **Host Compiler:** g++ with flags `-g -Wall -Wextra -fsanitize=address`
- **Build System:** GNU Make
- **Target Language:** `g--` (extension `.cm`)
- **Target Architecture:** Custom processor (defined in the related subproject)
- **Platform:** Linux

## Source Code Files

### `g--.cpp`

The compiler's entry point. It receives the source file (`.cm`) and the output binary name as arguments. It instantiates and coordinates the three phases: Lexer → Parser → Assembler.

```bash
./g-- program.cm output.bin
```

### `Lexer.cpp / Lexer.hpp`

Performs **lexical analysis**: scans the source code character by character and produces a sequence of tokens (`token_t`). It recognizes operators, reserved keywords (`int`, `void`, `if`, `else`, `while`, `return`), identifiers, numbers, and ASCII characters.

### `Parser.cpp / Parser.hpp`

Performs **syntax analysis** using an LL(1) grammar. It consumes tokens from the Lexer and constructs a **syntax tree** (`syntax_tree_t`) representing the program's structure. It implements error recovery using `backup()`.

### `Assembler.cpp / Assembler.hpp`

Walks the syntax tree generated by the Parser and produces the final **binary code** for the custom architecture. It implements arithmetic, logical, relational, and assignment operators.

### `Globals.hpp`

Defines the fundamental types shared among the phases:
- `token_t` — token types of the language
- `nonterminal_t` — grammar non-terminals
- `operator_t` — instruction set operations
- `tree_t<T>` — generic tree structure with cursor navigation

## Workflow

1. The user writes a program in the `g--` language (source file `.cm`).
2. The **Lexer** tokenizes the source file, identifying keywords, operators, and identifiers.
3. The **Parser** consumes the tokens and builds the syntax tree, validating the language grammar.
4. The **Assembler** traverses the syntax tree and generates the binary file containing the target architecture instructions.
5. The generated binary can be loaded into the custom processor (defined in `architeture/`).

## Example Program in `g--`

```c
// Factorial calculation (fact.cm)
int fact(int n) {
    if (n == 0) return 1;
    return n * fact(n - 1);
}
```

## Objetivo

- Definir uma gramática formal para a linguagem `g--` e gerar a tabela de parsing LL(1).
- Traduzir programas de alto nível para instruções de uma arquitetura de processador customizada.
- Explorar conceitos de análise de expressões, declarações, escopo e chamadas de função.

## Códigos-fonte

### `g--.cpp`

Ponto de entrada do compilador. Recebe como argumentos o arquivo-fonte (`.cm`) e o nome do arquivo binário de saída. Instancia e coordena as três fases: Lexer → Parser → Assembler.

```bash
./g-- programa.cm saida.bin
```

### `Lexer.cpp / Lexer.hpp`

Realiza a **análise léxica**: percorre o código-fonte caractere por caractere e produz uma sequência de tokens (`token_t`). Reconhece operadores, palavras-reservadas (`int`, `void`, `if`, `else`, `while`, `return`), identificadores, números e caracteres ASCII.

### `Parser.cpp / Parser.hpp`

Realiza a **análise sintática** usando uma gramática LL(1). Consome tokens do Lexer e constrói uma **árvore sintática** (`syntax_tree_t`) representando a estrutura do programa. Implementa recuperação de erros com `backup()`.

### `Assembler.cpp / Assembler.hpp`

Percorre a árvore sintática gerada pelo Parser e produz o **código binário** final para a arquitetura customizada. Implementa operadores aritméticos, lógicos, relacionais e de atribuição.

### `Globals.hpp`

Define os tipos fundamentais compartilhados entre as fases:
- `token_t` — tipos de tokens da linguagem
- `nonterminal_t` — não-terminais da gramática
- `operator_t` — operações do conjunto de instruções alvo
- `tree_t<T>` — estrutura genérica de árvore com navegação por cursor
